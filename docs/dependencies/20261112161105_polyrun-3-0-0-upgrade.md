# Upgrade polyrun 2.2.9 to 3.0.0

## Participants

Andrei Makarov (@amkisko)

## Dependency

polyrun development dependency. Base lock: 2.2.9. Target: 3.0.0. Manifest floor: `>= 3.0.0` in `activeadmin-autocompletes.gemspec`. Classification: dev or test only (CI parallel RSpec, coverage merge, failure merge, JUnit export, pressure benches).

## Symptom

Need current polyrun for `::RSpec` JUnit helper fix and `RSpecSupport` rename (RFC-0007). Local JUnit workaround and `Polyrun::RSpec` call sites would break or stay patched without the bump.

## Evidence

Upstream CHANGELOG 3.0.0 (https://github.com/amkisko/polyrun.rb/blob/main/CHANGELOG.md):

- BREAKING: `Polyrun::RSpec` -> `Polyrun::RSpecSupport` (`polyrun/rspec_support`); old constants/requires removed
- Fix `RspecJunit.install!` with `::RSpec` qualification
- Sus suite and Quick extensions (not used here)

Usage map in this tree:

- `spec/spec_helper.rb`: require + install hooks -> adapted to `RSpecSupport`
- `spec/support/junit_formatter.rb`: restored `RspecJunit.install!` with shard-aware paths
- `benchmarks/load.rb`: `Polyrun::Benchmark::Pressure` unchanged API
- CI / `usr/bin/release.rb`: `parallel-rspec --merge-failures` unchanged verbs

Upgrade class: `adapt-needed` (must rename support module; may drop local JUnit shim).

Resource compare (machine class arm64 Darwin; install path under Bundler sandbox gem home; n=1 observe-only):

- Install or graph storage (gem directory `du -sk`): base polyrun-2.2.9 = 1148 KiB; head polyrun-3.0.0 = 1160 KiB; delta +12 KiB
- Resident memory / CPU boot path: not sampled (dev tool; no product boot path). Inference only: no claim.
- Shipped gem size: not applicable (polyrun is development dependency; not in published runtime gem deps)

Verification: `POLYRUN_COVERAGE=1 bundle exec polyrun parallel-rspec --workers 5 --merge-failures` exit 0; `coverage/merged.json` present; five coverage fragments; pressure calibrate + L1 gate PASS.

## Suggested fix

Keep polyrun >= 3.0.0. No further shim.
